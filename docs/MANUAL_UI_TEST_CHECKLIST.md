## 使い方と試験前提

- 原本の通常版DBをバックアップし、復元した検証用DBへ接続した通常版UIで実施してください。既存の文献・履歴を使う試験もコピー側で実施します。公開デモは対象外です。
- この一覧を作る作業では、サーバー起動、DB変更、手動UIテストの実行、文献の確認済み登録は行っていません。
- 【環境操作】はターミナル・DB・ファイル操作等を伴い、UIのみでは完結しません。【準備必要】はUIに作成機能がない旧データ等、または大量データが必要です。未準備なら「保留」と記録します。
- P0＝誤った判定・時点混在・データ消失／上書きにつながる重要項目、P1＝主要機能・入力検証、P2＝操作性。まず各機能の正常系で試験データを作り、その後P0→P1→P2の順で確認します。
- 「期待結果」は受入基準です。現コードが満たすと保証した一覧ではありません。【要確認】【要仕様確認】は実装・仕様の懸念を含み、失敗を正常仕様として見逃さないための項目です。
- 1行で複数の値を指定した項目は、**値ごとに独立して試験**します。1つだけ試して行全体を合格にしないでください。
- 各行の結果を「未実施→合格／不合格／保留／対象外」に変更します。保留・対象外は理由必須。スクリーンショットにはQA症例を使ってください。
- 原本DBの故障・削除、実患者情報の新規入力、公開デモ更新、外部公開は不要です。破壊的な試験はコピーと隔離環境だけで実施します。

## 現コードから、特に結果を残してほしい仕様・実装上の懸念

これらは今回UIで再現した不具合の報告ではなく、チェックリスト作成時のコード確認で見つけた懸念です。今回、修正はしていません。

1. **精度指標の単位（R-18〜19）**：UI入力は0〜1を案内する一方、APIは正答率・感度・特異度に0〜100を許容し、表示は1以下を100倍する箇所があります。「1」が1%か100%か等を重点確認します。
2. **デフォルトアウトカムの編集（O-10）**：編集送信データにisDefault=falseが含まれるため、既定属性を意図せず解除する可能性があります。
3. **任意項目の削除（O-07）**：説明・単位の空欄がundefined送信となるため、既存の文字列が消えない可能性があります。
4. **複数の時点入力（M-17）**：基本情報の発症後日数、照合する評価時点、入院までの日数、評価日・段階はすべて同じ概念ではありません。矛盾や誤解に対する案内を確認します。
5. **実績の対象時点・尺度・未来日（F-18〜19）**：値と形式の検証はありますが、予測対象との一致や未来日を一律に禁止する仕様ではありません。結果の妥当性を自動保証すると解釈しないでください。
6. **CSVの並びと上限（X-10〜11）**：画面の症例別表示は評価日順、CSV抽出は保存日の新しい順になる箇所があります。「最新1000件」の意味を確認します。
7. **応答消失と再試行（S-16）**：連打抑止と保存トランザクションは、応答だけ失われた後の再試行による重複を完全に防ぐ仕組みとは別です。履歴確認を先に行います。
8. **文字列条件・追加項目の尺度**：通常UIにない項目にも数値入力欄を生成できますが、独自尺度の上限・分類の妥当性は自動で検証されません。

## UIだけでは証明できない範囲

- DB内の全行・JSONの一致、トランザクションの完全な巻き戻し、同時実行中の行ロック、外部接続拒否、数式解析の網羅性は別の自動／統合試験で補完します。
- バックアップのUI整合性検証は形式・チェックサムの確認です。復旧能力は実際に別DBへ復元して確認します。
- 文献と原著の一致、モデルの臨床妥当性、対象集団への適用可能性は、画面で正常動作することだけでは証明できません。
- 前回確認した旧履歴件数や文献件数は、今回の開始時点の件数と一致するとは限りません。開始時の実数を控えます。
- この計画は現在の5画面・7ルール種別・保存フローの範囲を対象にしています。未実装機能や将来追加機能の網羅性まで保証するものではありません。
