# RehabPredict 2.1：インストールと使い方

Windows・Mac用のデスクトップアプリです。**Node.js・MySQLのインストール、接続設定、管理者パスワードの入力は不要です。** 実行環境をアプリに同梱し、データはそのPCのSQLiteへ保存します。

## ダウンロードするファイル

[GitHub Releases](https://github.com/machamu-24/rehab-prediction-tool/releases/latest) のAssetsから、PCに合うファイルを選びます。`Source code` は開発用です。

| PC | ファイル |
| --- | --- |
| Windows（Intel・AMDの64bit PC） | `RehabPredict-2.1.0-Windows-x64-Setup.exe` |
| Apple Silicon Mac（M1・M2など） | `RehabPredict-2.1.0-macOS-arm64.dmg` |
| Intel Mac | `RehabPredict-2.1.0-macOS-x64.dmg` |

MacはAppleメニューの「このMacについて」でチップ／プロセッサを確認できます。macOS 13以降を対象にしています。WindowsはWindows 10以降の64bit環境を対象にしています。Windows ARM版は専用ビルドを提供していません。

## Windows

1. ダウンロードした `Setup.exe` を開き、インストーラーの案内に従います。通常の利用者権限で、その利用者向けにインストールします。
2. スタートメニューまたはデスクトップの **RehabPredict** を開きます。
3. 初回起動で文献データを自動準備し、照合画面を表示します。

## Mac

1. ダウンロードしたDMGを開きます。
2. **RehabPredict.app** を **Applications** へドラッグします。
3. Applicationsから **RehabPredict** を開きます。
4. 初回起動で文献データを自動準備し、照合画面を表示します。

DMGの中から使い続けず、Applicationsへコピーして利用してください。

## 初回起動と保存

- 初期データは、既存の23ルールに2026-11-11の4文献・7ルールを追加した **7アウトカム・30文献ルール** です。同じ研究の複数ルールを含む登録件数です。式・係数・適用条件・時間軸・URL・有効／無効状態を引き継ぎます。
- **新規利用は照合履歴・個別結果0件から開始します。** 症例入力・実績・メモ・利用者アカウント・バックアップ・接続情報は配布物に含みません。
- 「照合して履歴に保存」を押すと記録します。「保存せず照合」は保存しません。入力途中の値は、必要に応じて下書きまたは履歴へ保存してから終了してください。
- 終了はウィンドウを閉じるか、アプリのメニューから「終了」を選びます。保存済みの文献・症例・履歴は次回も利用できます。
- 各PCは独立しています。PC間でデータを自動共有・同期しません。原文リンクを開く場合などを除き、オフラインで利用できます。

## データの保存先

左メニュー「接続・バックアップ」に実際の保存先を表示します。アプリの「ファイル」→「データ保存先を開く」でも確認できます。

- Windows：`%LOCALAPPDATA%\RehabPredict`
- Mac：`~/Library/Application Support/RehabPredict`

SQLiteデータ、復元先の選択情報、バックアップを保存します。アプリ本体のフォルダーには保存しません。起動中のSQLiteファイルだけを直接コピーする方法ではなく、次のバックアップ機能を使ってください。

## バックアップ・復元

1. 「接続・バックアップ」→「バックアップを作成」を押します。
2. 必要に応じて「別の場所に保存」で、JSONファイルを外部媒体などへ保存します。
3. 復元は一覧の「このバックアップから復元」、または「バックアップファイルを選択」からJSONを選びます。
4. 文献・履歴などの件数を確認して「復元して切り替える」を押します。

**復元は別のデータファイルへ行います。** 切り替え前の状態は自動でJSONバックアップし、元のSQLiteファイルも残します。ファイルのチェックサム、各行の値、データの関連付けを確認してから切り替えます。失敗した場合は現在のデータを使い続けます。現在のJSON取り込み上限は40 MBです。

## 旧MySQL版から移行する場合

旧版で「バックアップを作成」を実行し、JSONバックアップを用意します。新しいアプリの「接続・バックアップ」→「バックアップファイルを選択」から読み込むと、文献と履歴をまとめて移行できます。旧MySQLそのものや旧版の接続設定は変更しません。

旧バックアップの保存日時に時差情報がない場合は、元のDBがこのPCと同じタイムゾーンだったか、UTCだったかを選択します。評価日・実績測定日の日付文字列自体は変更しません。判断できない場合は、元のDBの設定を確認してから移行してください。

旧版の実データを取り込んだ場合、そのPCの履歴は取り込んだ件数になります。初回配布の履歴0件という条件は、バックアップを取り込む前の新規状態です。

## アプリを更新する

1. 必要な入力を保存し、バックアップを作成してアプリを終了します。
2. Windowsでは新しいインストーラーを実行します。Macでは新しいappでApplications内の同じアプリを置き換えます。
3. 新しいアプリを開きます。

保存先はアプリ本体と分離しているため、利用者が追加した文献・履歴を保持します。同梱文献で利用中のDBを取り込み直すことはありません。将来の同梱文献の更新も、利用者の編集へ自動上書きしません。新しいDB形式を古いアプリで開いた場合は、データを変更せず停止します。

## 発行元確認について

今回の配布では、Windowsの発行元署名とAppleのDeveloper ID署名・公証は未設定です。Mac版はアドホック署名です。初回にOSの発行元確認・実行確認が表示される場合があり、組織のPC設定によっては管理者による許可が必要です。この版は確認操作なしのインストールまでは保証していません。

署名・公証済み配布を作成するには、それぞれの証明書とAppleの開発者アカウントが必要です。GitHub側へ証明書を設定すれば、配布ワークフローで署名・公証を有効にできます。OSの保護機能を一括で無効にする操作は不要です。

## 開発者向け

通常の利用者は以下のコマンドを実行する必要はありません。

```sh
pnpm install --frozen-lockfile
pnpm check
pnpm test
pnpm desktop:dist
```

`desktop:dist` は実行したOS用のインストーラーを作成します。Windows版はWindows、Mac版はMacのGitHub Actionsで作成します。Macは `pnpm exec electron-builder --config desktop/electron-builder.config.cjs --mac --arm64 --publish never` のように対象CPUを指定できます。Electron 45.2.3、electron-builder 26.18.0を固定しています。SQLiteは同梱Node.jsの内蔵モジュールを使い、外部のDBサーバーやネイティブ追加モジュールを必要としません。

最新文献の配布データ作成は `pnpm export:release-literature`（利用中のSQLite）、または `pnpm export:release-literature -- --sqlite <ファイル>` を使います。旧MySQL版のDBから書き出す場合は `node scripts/export-release-literature.mjs --mysql` を使用します。文献・アウトカムの許可した列だけを読み、履歴テーブルは読みません。内容を確認して `release/literature.seed.json` をコミットしてからReleaseを作成します。

GitHub ActionsはWindows x64・Mac arm64・Mac x64でインストーラーを作成し、実際のアプリを起動して初期履歴0、照合保存、文献編集、バックアップ復元、再起動を検証します。アプリのASAR内も検査し、症例DB・接続設定・開発依存の混入を拒否します。成功した配布物だけをReleaseへ添付します。

署名用Secrets：Windowsは `WIN_CSC_LINK`・`WIN_CSC_KEY_PASSWORD`、Macは `MAC_CSC_LINK`・`MAC_CSC_KEY_PASSWORD`。Apple公証にはさらに `APPLE_ID`・`APPLE_APP_SPECIFIC_PASSWORD`・`APPLE_TEAM_ID` を設定します。秘密値をソースや配布物へ登録しないでください。
