# RehabPredict 通常版の使い方

更新日: 2026-11-09。通常版の操作ガイドです。Windows・Macへの新規配布と配布版の起動は [RELEASE_GUIDE.md](RELEASE_GUIDE.md) を参照してください。以下の起動・開発用コマンドは従来のソース版向けです。

## Koyama対数曲線モデル（FIM総得点）

アウトカム「FIM総得点」で、文献「FIM総得点の対数曲線予測（Koyamaら2005／小山2018総説に基づく）」を利用できます（通常版の文献ID: 60013）。原著本文は未確認で、2018年総説p.773〜776・図2と原著公開抄録を根拠とする参考予測です。

「Koyama対数モデル（FIM総得点・2時点）」に、A（回復期入院時）とB（再評価時）の発症後日数・FIM総得点、X（予測対象）の発症後日数を入力します。すべて発症日＝0日からの累計日数です。14〜42日はAとBの評価間隔で、Bに入力する値ではありません。例えばAが発症後30日で、その14日後に再評価した場合はBに44を入力します。Koyama専用の時間軸にはB・Xが自動反映されるため、同じ日数を二重入力する必要はありません。他のモデルと同時に照合する場合も、Koyamaは専用入力のBからXへの将来予測を行い、上部の時間軸は他の文献の照合に使います。入力済みの「発症から入院までの日数」「入院時 FIM総得点」と上部の「予測したい時点（日・整数）」を、専用欄のA日数・A総得点・X日数へ自動反映します。自動反映中は元の欄の変更・削除にも追従します。専用欄で個別に編集するとその値を優先し、「上の入力との連動に戻す」で再び自動反映に戻せます。下書きの復元でもこの状態を保持します。入院日数は回復期入院までの日数を指定してください。現在のFIMや運動FIMだけの値、上部の評価時点をBへ転用しません。

初発・発症前ADL自立・テント上病変・車いす入院・片麻痺・脳梗塞または脳出血・回復期病棟の条件を確認し、未確認なら未評価のままにします。Aは発症30〜60日、A→Bは14〜42日、B<X≤180日で計算します。180日は総説の「約半年」を換算したアプリの上限で、厳密な検証境界ではありません。低下例と範囲外の計算値は通常の予測表示を停止し、横ばいは注意を付けます。

入院時・現在のFIM総得点は、それぞれ同じ評価時点の運動項目と認知項目を両方入力すると自動計算します。例：入院時運動25点＋入院時認知15点＝入院時総得点40点。この40点はKoyamaのAにも自動反映します。自動計算中の総得点欄は読み取り専用で、どちらかの点数を変えると再計算します。片方が未入力・入力途中・範囲外なら合計しません。総得点だけが分かる場合は手入力できます。入院時と現在の点数を混ぜて計算しません。

総得点の範囲は18〜126点です。指定日の点数と計算内訳を「数値予測の照合結果」に表示し、支持・困難の集計に含めません。架空例としてA=30日・40点、B=45日・55点、X=90日で80.64点になります。運動FIMの他施設検証111例・ICC=0.89を、この総得点モデルの精度として表示しません。項目別ADL自立や自宅復帰も判定しません。

## 起動と終了

1. MySQLを起動しておきます。接続先はプロジェクト直下の`.env`の`DATABASE_URL`です。接続情報を公開リポジトリへ登録しないでください。
2. Finderで`Start RehabPredict.command`をダブルクリックします。通常版をビルドし、ブラウザを開きます。既に同じポートで起動していれば、その画面を開きます。
3. 左メニューの「接続・バックアップ」で「準備ができています」を確認します。
4. 終了は起動用ターミナルで **Control + C**。ブラウザを閉じるだけではサーバーは止まりません。

ターミナルからはプロジェクト内で`pnpm local:start`。PORT未設定時の標準URLは`http://localhost:3020/`です。`.env`にPORTがあればそちらを優先します（このMacの現在の設定は3000）。ポートが使用中なら空きポートを選び、起動ログとブラウザに実際のURLを表示します。

Node.js、pnpm、インストール済み依存パッケージ、MySQLを使用するブラウザアプリです。単体のネイティブ`.app`ではありません。今回のMacでは設定済みです。別のPCへ移す場合は依存環境とDBの準備が必要です。`pnpm build`は通常版、`build:demo`は公開デモ用なので、通常版の更新では実行しません。

## 照合と保存

- アウトカムと「将来予測／同時点の判別」を選ぶと、その文献に必要な入力欄を表示します。膝伸展筋力など、同時点の判別にだけ使う項目は将来予測では通常表示しません。日数未指定でも予測種別に合う項目は表示し、時間軸未登録の文献の項目も残します。「すべての評価項目を表示」で他の評価値も記録できます。切替で非表示になった入力値は保持され、元の種別へ戻すと再表示されます。
- 入院時の値は「入院時評価」に、現在の評価値は各評価欄に入力します。変化量は入棟時から1ヶ月後までの差です。空欄と「なし／0」は異なります。
- BBS/FBSは0〜56、MMSEは0〜30、CBAは6〜30、FIM運動は13〜91、FIM認知は5〜35、要介護認定区分は0〜5、入院時FIM歩行は1〜7、FMA下肢は0〜34の整数を入力できます。入院時・現在の両方に適用し、入力欄内の薄い範囲表示も残しています。
- 範囲外の数字・小数・文字の入力や貼り付けは受け付けません。FIM運動の「13」などを入力する途中の1桁は、範囲内の点数になるまで計算・下書きには使いません。未完成のまま入力欄を離れると空欄になります。古い下書きに範囲外の点数があれば、該当項目を空欄にして復元します。
- 入院時FIM歩行項目はFIM運動・認知の次に、入院時の要介護認定区分は同じ欄の最後に表示します。
- FIM運動項目では、Koyama専用欄は通常表示しません。片麻痺の有無は共通の基本情報欄に表示します。Ikeueら2026の入棟3週後FIM運動項目合計は「入院時」でも入力欄と切り替え案内を表示します。「入棟3週間後の評価に切り替える」を押すか、評価時点で「入棟3週間後」を選ぶと入力できます。入院時の照合・履歴保存には3週後の値を含めません。
- 歩行自立で必要なΔBBS・ΔFIMの入力欄は「入院時」「入棟3週間後」でも表示します。これらの時点では入力を無効にし、「入棟1ヶ月後の評価に切り替える」を押すと3つの変化量欄をまとめて入力できるようにします。「入棟1ヶ月後」「経過評価」「退院時」で入力・照合できます。入院時・3週間後の照合・履歴保存には変化量を含めません。入力済みの値はタブ内に保持し、後の評価時点に戻すと再利用できます。経過評価・退院時でも変化量の対象期間は「入棟時→1ヶ月後」です。
- 同じ症例を追うときは、毎回同じ匿名症例IDを使用します。IDは英数字と`_`・`-`、最大64文字。評価日と評価時点も設定します。
- 「保存せず照合」は計算のみ。「照合して履歴に保存」は入力、結果、使用文献・定義、計算版をまとめてDBへ保存します。
- 入力を変更すると、表示中の結果が古いことを案内します。新しい入力で再照合してください。
- 下書きは明示的に保存した時点の内容をこのタブのセッション領域に保持します。再読み込み後に復元できます。タブを閉じると失われるため、永続保存には履歴を使います。リセットすると症例ID・入力・下書きも消えます。

結果は「条件への適合」「研究内の群別割合」「連続値の推定」を区別します。複数文献の支持割合や研究群内の割合は、個人の回復確率ではありません。「定義・文献の照合記録あり」は出典との整合性の記録で、臨床妥当性の認証ではありません。原著の対象・評価時点・除外条件を確認して利用します。

## 自動計算できないノモグラムの表示（2026-11-09）

有効なノモグラム文献で自動計算に必要な情報が未登録・未対応の場合も、登録された評価項目を入力すると「参考文献（原文確認）」に表示します。予測値や確率は算出せず、支持・困難の件数とその分母、計算できたルール数には含めません。

カードには計算できない理由、必要項目の入力状況、登録済みの適用条件、文献の補足、原文へのリンクを表示します。不足項目や明らかな条件不一致がある場合は「判定対象外」に表示します。対象条件や時間軸が未登録の場合は適用できると判断せず、原文で確認してください。池上ら2025の入棟時モデルで使う日数には「発症から入院までの日数」を入力し、現在の評価日数で代用しません。

新しく保存した履歴は保存時の参考表示を再表示でき、文献ごとの詳細CSVでは`literature`区分として出力します。旧履歴の表示や判定は、保存時の記録を保持します。

## 履歴と症例の推移

「照合履歴」で症例IDを指定すると、その症例の記録を評価日順に確認できます。20件ずつ表示し、ページ内の推移表と個別履歴を参照できます。実績・メモは各履歴から追記します。実績には測定日、発症後日数、尺度を必須で記録します。FAC・FIM運動・FIM認知・FIM合計・二値は範囲と整数を検証し、自由記述の尺度は名称・単位を残します。記録日と実際の測定日は別です。旧実績の時点は推測で補いません。

履歴を開くと「保存された入力値」を入院時評価・運動機能・ADLなどの表で確認できます。日本語の項目名・単位を表示し、0や「なし」「介助必要」も省略しません。保存された値は表示時に再計算しません。

履歴の詳細、または「文献照合」→「保存済み症例を選択」から過去の入力を再利用できます。選択画面は症例IDで完全一致検索でき、20件ずつ表示します。読み込むと現在のフォームを置き換えるため、残したい入力は先に「下書きを保存」で保持してください。

- **この入力で再照合**：保存時の評価日・評価時点・入力値・時間軸を読み込みます。その後「保存せず照合」または「照合して履歴に保存」を押すと、現在の文献で照合します。保存すると新しい履歴になり、元の履歴は保持します。
- **次回評価へ引き継ぐ**：症例ID・病型などの固定情報・入院時評価・記録済みの3週時点などの既往評価を引き継ぎます。評価日は今日、評価時点は「経過評価」にします。今回の測定値・変化量・評価／予測対象の日数は空欄になるので、新しい値を入力し、実際の評価日・評価時点に変更してください。「前回の評価値を参照」で元の評価日付きの値を確認できます。

旧履歴の評価日が未記録の場合は今日の日付で補いません。再照合前に評価日などを確認してください。現在の入力形式・点数範囲に合わない値は読み込み時に空欄とし、対象項目を案内します。FIMの内訳と保存された合計が異なる場合は、フォームでは内訳から合計を再計算し、案内を表示します。元の履歴の値は変更しません。

CSVは現在の条件の最大1,000履歴を出力します。従来の要約CSVに入院時評価・照合時間軸・実績時点と尺度・全入力JSONを追加しました。「文献ごとの詳細CSV」は1文献1行で数値予測、時間軸の判断、集計区分、保存時の文献・結果JSONを出力します。個別結果がない旧履歴も「詳細未保存」の行を残します。

新しい履歴では、使用時点の文献定義と出典を詳細内に保存しています。後日の文献変更で過去の結果を置換しません。旧履歴36件には個別判定が保存されていなかったため、その詳細を復元することはできません。架空の再計算結果で補完していません。

履歴で使った文献も削除できます。文献一覧と今後の照合対象から削除されますが、過去の照合履歴と履歴に保存済みの文献情報・判定結果は残ります。無効化を選んだ場合は、文献一覧に残して今後の照合から外せます。

## 文献の編集

### フォームで文献を登録する（2026-11-09）

新規登録で基本情報と時間軸を入力し、「判定ルール」で原著の評価項目・条件・数値を設定します。JSONの入力は不要です。入力後に「プレビュー」を押すと確認画面へ進みます。プレビュー後に内容を変更した場合は、再度プレビューしてから登録・更新します。新規登録で時間軸が未設定の場合は、時間軸タブへ案内します。日数が分からない場合は原著表記や確認できない理由を記録してください。

| ルールタイプ | 入力方法 |
| --- | --- |
| カットオフ値 | 評価項目・閾値・結果の説明。判定に用いる補助条件も追加可能 |
| 重回帰式 | 切片・各項目の係数・数値予測／閾値判定 |
| ロジスティック回帰 | 切片・非標準化係数・カテゴリ変換・確率のみ／文献の閾値での判定 |
| 決定木 | 分岐条件・満たす／満たさない場合の進み先・終端の結果を選択。開始位置と循環・参照切れも確認 |
| スコアリング | 評価項目ごとの点数区分・加点・合計点の閾値。各項目で上から最初に一致した区分を採用するため、必要に応じて区分を「上へ」で移動 |
| 複合条件 | 「すべて満たす」「いずれかを満たす」「満たさない」を組み合わせて条件やグループを追加 |
| ノモグラム | 必要な評価項目と自動計算しない理由を入力し、原文確認用の参考文献として登録。既存の計算対応モデルは係数フォームで編集 |
| カスタム数式 | 評価項目・演算子を押して数式へ挿入し、原著の係数や括弧を入力。Koyama専用モデルは既存の式・評価項目を固定して保持 |

確率の判定閾値と研究内割合は％で入力します（例：70）。カテゴリを数値へ変換する場合は、原著の符号化を入力してください。未入力の数値は0で補いません。文献の注記・時間軸・カテゴリ対応などは、フォームで触れない項目も保持します。必要な場合は「詳細編集（JSON）を開く」から確認できます。

### 病型を脳梗塞・脳出血に限定する

「適用条件」で「条件を追加」→評価項目「病型」→条件「次のいずれかに一致」を選び、「脳梗塞」「脳出血」をチェックします。「くも膜下出血」「その他」は選びません。プレビューには「脳梗塞 または 脳出血のいずれか」と表示します。複数の適用条件の行どうしは、すべて満たす（AND）条件です。従来の「くも膜下出血と等しくない」「その他と等しくない」の2行もそのまま動作し、自動で書き換えません。

参考表示用のCoxノモグラムは、計算用の切片・係数・支持／困難メッセージがなくてもプレビュー・登録・編集できます。入力済みの数値や評価項目名・時間軸は検証します。プレビューには「自動計算なし・原文確認」と必要な評価項目を表示し、コンセンサス集計は無効にします。自動計算するロジスティック型ノモグラムには、引き続き切片・係数などが必要です。

文献は登録・修正して保存すると利用できます。別途の再照合操作や確認メモの登録は不要です。既存の再照合待ち・確認状態のない文献も、確認状態だけを理由に計算から除外しません。

式や適用条件の不備・未対応モデルは引き続き計算対象外です。根拠不足などの理由で明示的に計算対象外とされた既存文献も、その理由を表示して除外します。

文献を開いてから他の画面で更新された場合は上書きを拒否します。編集中の内容を控えてから、一覧を再読み込みして開き直してください。

原著照合の結果は[LITERATURE_AUDIT.md](LITERATURE_AUDIT.md)に記載しています。旧`seed*.mjs`や`fix*.mjs`は過去の取り込み・補修用です。現在のDBを初期化・更新するために再実行しないでください。

## バックアップと復元

「接続・バックアップ」→「バックアップを作成」で`backups/`に保存します。コマンドは`pnpm local:backup`。ファイルにはアウトカム・文献・入力・履歴・実績が含まれます。DB接続パスワードや`.env`は含まれません。ファイルの整合性検証は形式とチェックサムの確認です。別の保存媒体にコピーすれば、PC故障時の備えになります。

復元は **新しいDBへ** 行います。アプリを終了してから、例のファイル名を実際のバックアップ名に置き換えて実行します。

```sh
pnpm local:restore rehab-YYYY-MM-DDT...json rehab_restore_example
```

復元先名は`rehab_restore_`で始め、その後は英数字と`_`にします。既存DBへの復元は拒否されます。プログラムに同梱したテーブル定義を使い、全行・全フィールドの一致を検証します。元のDBがなくても復元できます。成功後、`.env`の`DATABASE_URL`のDB名部分だけを復元先名へ変更し、再起動して履歴を確認します。元DBは残ります。失敗時は元DBの設定で使用を続けられます。

このJSONバックアップはアプリの4テーブル用です。MySQLサーバー全体、ユーザー権限、OAuthアカウント、プログラム本体は別途保管します。元DB自体を失った場合も、MySQLサーバー・DB作成権限・この版のプログラム・バックアップがあれば復元できます。接続URLの元DB名が存在しなくても復元処理は動作します。

## DB更新・問題の切り分け

既存の通常版DBの追加列・索引は`pnpm local:migrate`で更新します。変更前にバックアップし、既存行を保持して不足部分だけを追加します。今回のDBには適用済みです。過去の履歴に新しいスナップショットは遡って追加しません。

- 接続不可: MySQL起動状態と`.env`の接続先を確認。
- DB更新が必要: アプリを終了し`pnpm local:migrate`後に再起動。
- ビルド失敗: ターミナルのエラーを確認。ソース更新後は`pnpm check`・`pnpm test`・`pnpm build`で確認可能。
- 通常版はループバックアドレス専用です。別のPCからの共同利用に必要な認証・権限管理は対象外です。

`db:push`は旧Drizzle履歴を使う開発用コマンドです。今回の既存DBには追加列を適用済みのため、通常運用の更新には上記`local:migrate`を使用します。

## 文献の時間軸（2026-11-06更新）

新規登録・編集の「時間軸」タブで、評価時点と予測対象時点を発症日＝0日とした日数で登録します。入力単位は「日」に統一しました。月単位の文献は1ヶ月＝30日の目安で換算し、概算であること・原著表記・換算方法を残します。既存の月単位データも読み込めます。

- 明確な時点、概算、研究集団の平均値、中央値、特定できない、を区別します。
- 入院時・退院時・評価から4週後などの原著表記と、発症起点へ換算した根拠（ページ・表・計算方法等）を残します。平均や中央値を個々の患者の厳密な適用条件として扱いません。
- 例えば評価が発症後30日で、その評価から28日後を調べる文献なら、予測対象は発症後58日です。元の評価日数が概算なら、算出した対象時点も概算として記録します。
- 時間軸・原著表記・根拠の入力は任意です。未入力でもプレビューの更新・登録ができます。値を特定できない場合は日数を作らず、「特定できない」を選択し、必要に応じて理由を記録します。
- 同時点の判別は将来予測と区別します。明確な日数で予測対象時点が評価以前になる将来予測は登録できません。
- 文献一覧・登録前プレビュー・照合結果・新規履歴に時間軸を表示します。時間軸の編集も保存後すぐに反映されます。

時間軸未登録の既存文献には日数を推測で補完しません。照合画面で「評価値を測定した時点」「予測したい時点」を指定します。両方とも発症からの日数です。評価日・評価時点の名称は履歴管理用で、時間軸の数値を自動的に決めません。入院時の値で照合するなら入院時の発症後日数を指定してください。

- 日数差の上限は設けません。平均値・中央値・概算、時点不明・未登録でも、ほかの集計条件を満たす二値判定を支持・困難に含めます。
- 平均値・中央値・概算、時期の違い、確認用の範囲外、時点不明・未登録には、中立的な「評価時期の確認」ラベルを表示します。範囲内の平均値・中央値にも表示し、確認操作は要求しません。
- 将来予測と同時点判別の種類の違い、適用条件外、入力不足、文献の集計除外設定は引き続き反映します。数値予測・記述型出力は支持・困難に加えません。
- サマリーには集計対象件数と、そのうち評価時期の確認が必要な件数を表示します。各文献には評価時点・アウトカム測定時点・原著表記を表示します。

管理者は評価・予測対象それぞれに、時期の確認用の範囲と設定理由を任意で登録できます。範囲外でも日数差だけでは集計から除外しません。日数や範囲は推測で補完せず、保存時には指定時間軸と照合結果を一緒に残します。過去の履歴の集計は変更しません。詳しい手順は[TIME_MATCHING.md](./TIME_MATCHING.md)を参照してください。
